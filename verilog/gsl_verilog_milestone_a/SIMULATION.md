# Running the Verilog simulations

How to install the tools and run the self-checking testbenches for the GCC-PHAT blocks in `verilog/`.

| Folder | Block | Testbench checks |
|---|---|---|
| `fft2048/` | 2048-point FFT/IFFT engine + buffer bank | DC, 1 tone, 2 tones, arbitrary complex, IFFT round trip; bit-exact vs Python model |
| `xspec_phat/` | Channel unpack, 6 cross-spectra, PHAT, IFFT packing | Full chain (FFT ×2 → xspec_phat → IFFT ×3) on 4 signal cases; bit-exact + TDOA accuracy |
| `gcc_engine/` | **Milestone A**: complete GCC-PHAT core (loader, FFT, xspec, peak search, sequencer) | 10 jobs incl. realistic shots from `python/gs_gen_*`; bit-exact, TDOA accuracy, shooter bearing |

---

## 1. Software needed

| Software | Purpose | Needed? |
|---|---|---|
| Icarus Verilog 11+ (tested 12) | Verilog simulator | Yes |
| GNU make | Runs the build / check steps | Yes |
| Python 3.8+ | Bit-true models and checks | Yes |
| numpy | Accuracy checks, `make model` in `fft2048` | Yes |
| scipy | Your signal generator (`python/gs_gen_*`) and the MB decimator stand-in, used by `gcc_engine` | Yes (for `gcc_engine`) |
| GTKWave | Viewing waveforms | Optional |
| ModelSim / Questa (ships with Quartus) | Alternative simulator | Optional |

---

## 2. Install

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y iverilog make python3 python3-numpy python3-scipy gtkwave unzip
```

### Windows (via WSL)

WSL runs a real Ubuntu inside Windows and is the easiest route.

1. Open PowerShell **as Administrator** and run:
   ```powershell
   wsl --install
   ```
2. Reboot.
3. Open **Ubuntu** from the Start menu and create a user name and password.
4. Run the Ubuntu commands above.

Your Windows drive is visible inside Ubuntu at `/mnt/c/` (for example `/mnt/c/Users/<you>/Downloads/`). On Windows 11, GTKWave opens directly from WSL. On Windows 10, install GTKWave for Windows and open the `.fst` file from Windows.

### macOS (Homebrew)

```bash
xcode-select --install
brew install icarus-verilog
pip3 install numpy scipy
brew install --cask gtkwave      # optional; can be fiddly on recent macOS
```

## 3. Check the install

```bash
iverilog -V | head -1
make --version | head -1
python3 -c "import numpy, scipy; print(numpy.__version__, scipy.__version__)"
```

Each command should print a version. An error means that tool is not installed yet.

## 4. Folder layout

`xspec_phat` uses files from `../fft2048`, and `gcc_engine` uses both plus your generator in `../../python`, so keep this layout:

```
GSL/
├── python/                  (your generator + detection scripts)

    ├── xspec_phat/
```

## 5. Run `fft2048` (~1.5 min)

```bash
cd GSL/verilog/fft2048
make
```

Expected end of output:

```
TEST 5: IFFT round trip of test 4
  ...
  -> PASS

============================================================
 ALL TESTS PASSED
============================================================
tb_vec_1.txt: inverse=0 exp rtl=11 model=11  mismatching bins=0  -> BIT-EXACT
...
tb_vec_5.txt: inverse=1 exp rtl=4 model=4  mismatching bins=0  -> BIT-EXACT
ALL BIT-EXACT
```

Most of the run time is the testbench's double-precision reference DFT, not the FFT itself.

---

## 6. Run `xspec_phat` (~45 s)

```bash
cd ../xspec_phat
make
```

The simulation prints four `-> PASS` lines and `ALL TESTS PASSED`. The Python check then prints, for each test:

```
=== tb_xp_3.txt:
  Z0/Z1 (fft2048)     : BIT-EXACT  exps (4, 4)
  W0..W2 (xspec_phat) : BIT-EXACT
  R0..R2 (IFFT)       : BIT-EXACT  exps (9, 9, 9)
  pair   truth   coarse  fpga16x  float16x  repo16x | fixpt err  ...
  ...
  worst fixed-point TDOA error: 0.195 us (budget 1 us)
```

and finally:

```
ALL CHECKS PASSED
```

Column meanings:

| Column | Meaning |
|---|---|
| `truth` | True TDOA from the test geometry, in samples |
| `coarse` | Integer peak found in the RTL correlation |
| `fpga16x` | RTL correlation refined with windowed-sinc on a 1/16-sample grid (as planned for HPS / Nios) |
| `float16x` | Same refinement on a double-precision GCC-PHAT of the same windows |
| `repo16x` | `gs_det_tdoa.gcc_phat` algorithm on the unpadded windows |
| `fixpt err` | `fpga − float` on a 1/256-sample grid: the fixed-point error |

## 6b. Run `gcc_engine` — Milestone A (~3 min)

```bash
cd ../gcc_engine
make
```

`make` runs three steps:

1. `python3 milestone_a.py prepare` builds 10 jobs: 4 synthetic, plus one SW and one MB job from each of 3 scenarios generated by your `python/gs_gen_*` scripts (written to `gen_work/`).
2. The simulation runs every job through `gcc_engine` and prints one `-> PASS` per job, a back-to-back throughput test, and `ALL RTL CHECKS PASSED`.
3. `python3 milestone_a.py check` prints a TDOA table and (for MB jobs) the shooter bearing per job, ending with:

```
============================================================
 Milestone A: PASSED  (bit-exact, fixed-point error <= 1 us [worst 0.195], <= 2 ms per job)
============================================================
```

If `../../python` is missing, `prepare` skips the realistic jobs and runs the 4 synthetic ones. Use `python3 milestone_a.py prepare --python-dir <path>` to point at your generator elsewhere.

## 7. Waveforms (optional)

```bash
make wave
gtkwave tb_xspec_phat.fst &        # in xspec_phat/
gtkwave tb_fft2048.fst &           # in fft2048/
```

`make wave` writes FST, which is much smaller than VCD (~50 MB vs ~900 MB for `xspec_phat`).

Useful signals:

| Testbench | Expand | Signals |
|---|---|---|
| `tb_fft2048` | `dut` | `state`, `stage`, `ctr`, `sh_cur`, `exp_acc`, `fft_done` |
| `tb_xspec_phat` | `u_xp` | `state`, `slot`, `ph`, `w_we`, `w_waddr` |
| `tb_xspec_phat` | `u_fft` | `fft_done`, `fft_bfp_exp` |
| `tb_gcc_engine` | `dut` | `state`, `res_valid`, `job_ready`; `dut.u_peak` → `m`, `state` |

## 8. All `make` targets

| Command | What it does |
|---|---|
| `make` | Simulation + Python check (in `gcc_engine`: prepare → simulation → check) |
| `make sim` | Simulation only |
| `make check` | Simulation + Python check |
| `make wave` | Simulation with an FST waveform dump |
| `make model` | Python model vs numpy (`fft2048` only) |
| `make prepare` | Build the Milestone A jobs (`gcc_engine` only) |
| `make clean` | Delete generated files (`.vvp`, waveforms, `tb_*.txt`) |

## 9. Alternative: ModelSim / Questa (from Quartus)

Newer Quartus versions ship Questa – Intel FPGA Edition, which needs a free license from Intel's licensing site.

```bash
# fft2048
cd GSL/verilog/fft2048
vsim -c -do do_fft2048.do
python3 fft2048_model.py check tb_vec_*.txt

# xspec_phat
cd ../xspec_phat
vsim -c -do do_xspec_phat.do
python3 xspec_phat_model.py check tb_xp_*.txt
```

Drop `-c` to open the GUI with the waveform signals already added.

## 10. Troubleshooting

| Symptom | Fix |
|---|---|
| `iverilog: command not found` | Install the tools (section 2) |
| `No module named numpy` / `scipy` | `sudo apt install python3-numpy python3-scipy` |
| `ma_jobs.txt not found` | Run `make` (or `make prepare`) in `gcc_engine` before `make sim` |
| `generator step ... failed` | Your `python/` scripts or `gen_config.ini` changed; run the printed command by hand to see the error |
| `error: externally-managed-environment` from pip | Use the apt package above, or a Python venv |
| `No rule to make target '../fft2048/...'` | `fft2048` and `xspec_phat` are not side by side (section 4) |
| `$readmemh: Unable to open tw2048_re.hex` | Run `make` from inside the block's folder |
| `Makefile:NN: *** missing separator` | A Windows editor replaced tabs or line endings; restore the Makefile from the repo |
| A test prints `FAIL` | Read the `FAIL:` line above it; then rerun `make wave` and inspect the signals in section 7 |
